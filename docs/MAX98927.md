# Lavender speaker amp ("maxim,max98927L") — it is a MAX98937 register map

[R] = read in source, [I] = inference. Source repo: `MiCode/Xiaomi_Kernel_OpenSource`,
branches `lavender-q-oss` and `lavender-p-oss` (driver identical except comments).

## 1. Key finding

- Xiaomi has **no** `max98927.c`. The node `compatible = "maxim,max98927L"` binds to
  `sound/soc/codecs/max98937/max98937.c` (DAI link selected by `CONFIG_SND_SOC_MAX98937` in
  `sound/soc/msm/sdm660-internal.c` under `#elif defined(CONFIG_SND_SOC_MAX98937)`). [R]
- The driver handles **two chips** with **different register maps**: MAX98927 and MAX98937.
  `check_max98927_presence()` reads 0x01FF (98927 REV_ID); if bit6 set -> MAX98927, else reads
  **0x0600** (98937 REV_ID); if bit6 set -> MAX98937. [R]
- Our chip returns 0 at 0x01FF and drops writes at 0x0082+ (98937 map ends at 0x0081, then
  0x0500/0x0501/0x0600) -> **our chip is a MAX98937** [I, strong]. All mainline-98927 addresses
  >= 0x001E are shifted by 1–3 on the 98937, and GLOBAL_EN is **0x0500**, not 0x00FF.
- Readback anomalies explained by the 98937 bitfields (from `max98937.h`) [R+I]:

| Addr | 98937 name | Valid bits | Our write -> read | Explanation |
|---|---|---|---|---|
| 0x0022 | PCM_STATUS_WORD_CONFIG_2 | b7, b0 | 0x22 -> 0x00 | b1,b5 don't exist |
| 0x0024 | PCM_Master_Mode | MSTR[1:0], MCLK_RATE[5:2], CLK_SRC b6 | 0x88 -> 0x08 | no b7 |
| 0x003F | Boost_Control_0 | BST_VOUT[4:0], EXT_PVDD_EN b7 | 0xF7 -> 0x97 | b5,b6 don't exist |
| 0x0042 | Meas_ADC_Config | 3 bits | 0x3E -> 0x06 | upper bits don't exist |
| 0x0082/86/87 | (none) | — | -> 0 | beyond 0x0081 |
| 0x00FF, 0x01FF | (none) | — | -> 0 | GLOBAL_EN=0x0500, REV_ID=0x0600 |

Our dump decoded with the 98937 map shows why there is no sound: 0x23=0x08 (PCM_Mode_Config =
LEFT-justified, CHANSZ=0), 0x25=0x80 (BSEL=0 invalid), 0x26=0x01 (SR=11.025k), 0x3B=0x00
(speaker gain 0 = mute), 0x3A=0x01 (speaker source not PCM), and 0x0500 never written. [I]

## 3. Xiaomi init sequence for MAX98937 (`max98927_i2c_probe` + `max98927_parse_dt`) [R]

regulator handling (`MANUAL_DVDD_ENABLE 0`). Then probe reads REV_ID with retries 10..50 ms.

## 4. Stream path (`max98927_dai_hw_params`, `max98927_set_clock`, `max98927_stream_mute`) [R]

- The machine driver (`sdm660-common.c` `msm_mi2s_snd_startup`) only sets the **CPU** DAI fmt
  (CBS_CFS); it never calls the codec's `set_fmt` [R, grep] -> PCM_Mode_Config stays 0x40 from probe
  (I2S, slave via default 0x24=0). [I]
- hw_params, 16-bit 48 kHz, interleave 0 (all `regmap_update_bits`):
  0x0023 CHANSZ[7:6]=01; 0x0026 [3:0]=8; 0x0027 [7:4]=8 and [3:0]=8; 0x0025 BSEL[3:0]=2 (2*16=32).
- Unmute (playback start): `update_bits(0x0039, 1, 1)` then `update_bits(0x0500, 1, 1)`.
  If DT `safe_gain` set and DSM feedback off: 0x0036 vol=digital_safe_gain(44), speaker gain safe(1)
  (note: driver uses the 98927 Speaker_Gain address 0x003C here — bug, not used on lavender: no safe_gain in DT).
- Mute (stop): `update_bits(0x0500, 1, 0)` then `update_bits(0x0039, 1, 0)`.
- Capture stream (feedback IV to ADSP): 0x003D=0x03 on, 0x00 off; then `afe_dsm_set_calib()`.
- DSM (Maxim speaker protection) runs on the Q6 ADSP (`afe_dsm_*` externs, misc dev
  `dsm_ctrl_miscdev`, calibration RDC from file). **Not required** for the amp to output sound. [R+I]

## 5. Lavender DT (`arch/arm/boot/dts/qcom/sdm660-audio.dtsi`) [R]

`max98927@3a { compatible="maxim,max98927L"; reg=<0x3a>; mono_stereo_mode=<0>; interleave_mode=<0>;
maxim,98927-reset-gpio=<&tlmm 77 0>; }` — and a `tfa98xx@34` node shares reset GPIO 77 (alternate
NXP TFA98xx amp on some units; TFA reset is active-high) [R/I]. Our unit answers at 0x3A.

## 6. Why GLOBAL_EN may still read 0 (once at 0x0500) [I]

Check after enable: 0x0002 b7 PWRUP_DONE vs 0x0003 b0 PWRUP_FAIL, b3 BST_UVLO; 0x0002 b3 CLKSTOP.
Power-up needs BCLK/LRCLK present and matching BSEL (0x25) / SR (0x26); with 0x0011=0x03 the clock
monitor auto-restarts when clocks return. Thermal thresholds 0x14/0x15 and brownout (0x52) can also
force shutdown. On MAX98927 the equivalent registers are 0x00FF/0x0100/0x01FF (mainline).
